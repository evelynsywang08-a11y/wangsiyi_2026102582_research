## 二、报错/警告

### 1. 【报错】Read10X: Directory provided does not exist

- 在跑教程第一段，读数据时
- 报错内容：
  ```
  Error in Read10X(data.dir = "/brahms/mollag/practice/filtered_gene_bc_matrices/hg19/") :
    Directory provided does not exist
  ```
- 定位：报错里的路径是 `/brahms/mollag/practice/...`。回看教程原文确认，这是**教程作者自己机器的路径**，不是通用路径。我电脑上根本没有这个目录
- 解决：改成自己电脑的文件路径
   
   ```
   Read10X(data.dir = "/Users/evelyn/Desktop/PBMCs/filtered_gene_bc_matrices/hg19")
   ```

---

### 2. 【警告】Feature names cannot have underscores, replacing with dashes

- 解决：Seurat 5.x 的规定——基因名里不能有下划线 `_`，统一替换成短横线 `-`
- 忽略，是正常行为

---
### 3. 【报错】The RStudio Plots window may be too small to show this patchwork

- 在把两张图并排显示，plot1 + plot2
- 报错内容：
  ```
  Error in `value[[3L]]()`: ! The RStudio Plots window may be too small to show this patchwork.
  ```
- 定位查找：
  1. 先把 RStudio 的绘图面板拖到很大 —— 还是报同样的错，怀疑不是尺寸问题
  2. 通过AI指导，查 print.patchwork 的源码    
  （以下为AI解释）它把 `grid.draw()` 包在了 `tryCatch()` 里，任何 grid 层的错误都被替换成了这句"窗口太小"，绕开这个包装，直接调 `patchwork:::build_patchwork()` + `grid.draw()`，拿到真正的错误：
     ```
     Viewport has zero dimension(s)
     ```
- 结论：提示语具有误导性，真实原因确实是尺寸不够，`LabelPoints(repel = TRUE)` 内容更复杂所以对尺寸要求更高
- 解决：改用 `ggsave()` 直接存成文件，完全绕开绘图面板

---

### 4. 【报错】saveRDS: cannot open the connection

- 最后一步保存 Seurat 对象
- 报错内容：
  ```
  Error in gzfile(file, "wb") : cannot open the connection
  ```
- 定位查找【AI协助】：路径写的是 `"../output/pbmc3k_final.rds"`。`..` 表示上一级目录，从我当时的位置算出来是 `/Users/evelyn/Desktop/output`，这个目录不存在。而且saveRDS()不会自己创建目录
- 解决：
  1. 路径改成项目内的 `output/`
  2. 脚本开头加一行 `dir.create("output", showWarnings = FALSE)` 先把目录建出来

---

### 5. 【AI检查代码时发现】`ggsave()` 被注释掉，图没存出来

- 现象：教程里的 `ggsave()` 是注释状态，跑完脚本不会产出任何图片文件
- 解决：取消注释，并改好输出路径

- **定位查找**：教程里有两版最终绘图代码

    ```r
      xlab("UMAP 1") + ylab("UMAP 2") +
      theme(axis.title = element_text(size = 18),
            legend.text = element_text(size = 18)) +
      guides(colour = guide_legend(override.aes = list(size = 10)))
    ```

- **结论**：我的最终图添加了第二版代码，右边有图例。且教程末尾的代码没在图中显示，所以网页上能看到的最终图只有那张 `+ NoLegend()` 的图

### 3.【AI 协助确认】形状不一样的可能原因

与教程核对前面的数值，发现差异应该出在最后"把结果投影成二维图"这一步

AI给出的可能的原因有两个，如下：

1. **UMAP 的底层实现换了**

   教程是基于 Seurat 4 写的，那时候默认调用 Python 写的 umap-learn；
   Seurat 5 换成了 R 自己写的 uwot。
   两种实现算出来的二维坐标本来就不会一样，但"谁和谁挨着"这个关系是保持的，所以分群和注释的结果不受影响。

2. **UMAP 本身带随机性**

   uwot 用的是自己的随机数，不受 R 的 `set.seed()` 控制。
   所以就算配置和教程完全一样，图也不太可能一模一样。
